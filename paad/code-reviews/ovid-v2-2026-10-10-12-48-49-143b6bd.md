## Executive Summary

The branch is documentation and skill-status work for 2.0.0. It contains no correctness bug in executable logic. It does contain four Important accuracy defects in user-facing claims. The highest-impact ones are in README and paad-help. README says `/test-roadmap` is the only skill that commits code, and that it is the "one exception" whose security-pinning tests reach git. Both claims are false, because `/fix-architecture` (and `/vibe`, for commits) do the same. The draft release notes also drop the "no longer experimental" change. Confidence is high: every finding was corroborated by two or three specialists and confirmed against the current files.

## Important Issues

### [I1] "The only PAAD skill that writes and commits code" is false
- **File:** `README.md:1028-1030`; same claim at `preview/paad/skills/paad-help/SKILL.md:82-83` and `:711`
- **Bug:** README says "**This is the only PAAD skill that writes and commits code.** Every other skill reports, advises, or edits documents". paad-help repeats it twice. `/fix-architecture` commits safety-net tests in both commit modes, and commits each fix in auto-commit mode (`preview/paad/skills/fix-architecture/SKILL.md:243, 246, 297, 442`). `/vibe` says "this skill writes and commits source code" (`vibe/SKILL.md:219`). README's own fix-architecture bullet (~:869-870) contradicts the claim.
- **Impact:** Users decide from this sentence which skills may put commits on their branch. It names the wrong set.
- **Suggested fix:** Drop "only" in all three places, or narrow it (e.g. "the only skill whose main job is writing and committing tests"), and name fix-architecture and vibe as skills that also commit.
- **Confidence:** High
- **Found by:** Logic & Correctness, Spec Compliance, Contract & Integration (`claude-opus-5-5`)

### [I2] "`/test-roadmap` is the one exception by design" leaves out fix-architecture
- **File:** `README.md:711-713`
- **Bug:** `/fix-architecture` also commits the tests that pin a security flaw. It does so in both commit modes and gives them only neutral names (`fix-architecture/SKILL.md:297`). In manual mode, or after an "Attempted, reverted" outcome, a committed test reproduces a live weakness.
- **Impact:** This paragraph states the limits of the `paad/security/` protection. A reader who trusts it will not audit fix-architecture's safety-net commits.
- **Suggested fix:** Name both skills: "`/test-roadmap` and `/fix-architecture` are the exceptions by design: tests that pin a security finding are committed (with neutral names), and still reproduce the weakness."
- **Confidence:** Medium
- **Found by:** Security, Logic & Correctness, Contract & Integration (`claude-opus-5-5`)

### [I3] "whatever the skill" overstates which skills route security findings
- **File:** `README.md:701-703`
- **Bug:** "Any finding a skill produces that would help an attacker is written only under `paad/security/`, whatever the skill". Only the six `PRODUCERS` in `scripts/check_security.py:44-47` route findings there: agentic-owasp, agentic-review, test-roadmap, agentic-architecture, pushback and agentic-dedup. alignment, handoff, agentic-a11y, vibe and makefile write reports, `handoff.md` or commits, and none of them routes.
- **Impact:** A user may commit an alignment report or a `handoff.md` that records a weakness, believing it was diverted. Commit ba29852 set out to state the guarantee *with its limits*, and this is an unstated limit.
- **Suggested fix:** Scope the sentence to the six skills by name.
- **Confidence:** Medium
- **Found by:** Security, Logic & Correctness, Spec Compliance (`claude-opus-5-5`)

### [I4] Draft 2.0.0 release notes omit the "no longer experimental" change
- **File:** `v2-release-notes.md:79-104` (counterpart `CHANGELOG.md:21-22`)
- **Bug:** CHANGELOG `[Unreleased]` says `/rethink`, `/test-roadmap` and `/handoff` are no longer experimental and now carry the semver promise. The release notes never mention it. Every other `[Unreleased]` bullet has a counterpart in them.
- **Impact:** Users who pinned a version because of the old EXPERIMENTAL banners don't learn the semver promise now covers these three skills.
- **Suggested fix:** Add under "Other changes": "**`/rethink`, `/test-roadmap` and `/handoff` are no longer experimental.** Their arguments and output now carry the same semver promise as the other skills."
- **Confidence:** High
- **Found by:** Spec Compliance, Logic & Correctness, Contract & Integration (`claude-opus-5-5`)
