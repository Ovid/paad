## Important Issues

### [I1] `check-export-commands` reports success on every path where grep cannot run
- **File:** `Makefile:280-291`
- **Bug:** `bad=$$(grep -rnE "…" kiro_and_antigravity/skills || true)` makes a non-empty `bad` the target's only failure condition. Grep exiting 2 (missing, renamed, or unreadable export tree) yields an empty `bad`, and `|| true` discards the status. An empty `$(SKILL_NAMES)` produces the empty alternation `()`, which is a hard grep error, swallowed the same way. `check-export-frontmatter:257` has the same shape via `for file in $$(find …)`.
- **Impact:** A check that cannot report its own inability to run, inside a `make test` chain that ends in "All checks passed." Inside the full chain the blast radius is limited — `check-export-current` independently catches a missing export tree — but standalone (`make check-export-commands`, listed by `make help`) it lies outright, and it lies for the empty/malformed-name case even in the full chain. The sibling target immediately below handles the identical failure class correctly (`Makefile:297`), which is what makes this an omission rather than house style.
- **Suggested fix:** Capture the exit status instead of discarding it — `bad=$$(grep -rnE "…" kiro_and_antigravity/skills); st=$$?; if [ "$$st" -gt 1 ]; then echo "FAIL: grep could not scan the export (exit $$st)"; exit 1; fi` — and guard the alternation with `if [ -z "$$names" ]; then echo "FAIL: no skills found under $(SKILLS_DIR)"; exit 1; fi`.
- **Confidence:** Medium
- **Found by:** Error Handling & Edge Cases (`claude-opus-5[1m]`)

### [I2] `SKILL_NAMES` is interpolated into a shell string and a regex with no escaping
- **File:** `Makefile:281-282`
- **Bug:** `SKILL_NAMES := $(notdir $(SKILL_DIRS))` is filesystem-derived from `plugins/paad/skills/*`, and lands unescaped inside a double-quoted shell string. Backticks in a directory name pass through make into shell command substitution — reproduced in a scratch copy, where a directory named `` `whoami` `` yielded `names=ovid|vibe`. The second mode needs no attacker: a regex metacharacter in a legitimate skill name silently corrupts the `grep -E` alternation, so the guard under-matches instead of failing.
- **Impact:** A fork's directory name reaching a maintainer's shell when they run `make export && make test` on a PR branch. The silent-under-match mode is the more likely one and defeats the guard's entire purpose. The Python side of the same job does `re.escape` correctly at `convert_skills.py:88`; the Makefile copy does not.
- **Suggested fix:** Build the alternation in Python — `scripts/` already owns the escaped skill-name list in `_skill_command_re()` — and have the target shell out to it rather than reconstructing the pattern a second time in make. The pre-existing `for dir in $(SKILL_DIRS)` instances in `check-digraphs` / `check-help` / `check-readme` / `check-announce` share the shell-quoting half of this and are out of scope for this branch; the new target is not.
- **Confidence:** High
- **Found by:** Security (`claude-opus-5[1m]`)
