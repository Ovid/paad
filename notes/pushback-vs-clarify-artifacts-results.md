# Round 2: pushback vs clarify.md on AI-generated artifacts

Same `invoicer` fixture. Rubric pre-registered in `RUBRIC2.md`.
6 runs: 2 artifact types × 3 arms (no skill / clarify.md / pushback).

Round 1 tested specs. This round tests what people are actually running
pushback on: a stale steering file and paad's own generated report.

## Artifacts under review

**S5 — `CLAUDE.md`**, committed 2026-06-05, never updated. Seven planted
defects: JSON storage section (SQLite since `db43278`), a `--format json`
mandate (removed in `4e0f028`), two documented commands that don't exist,
a self-contradicting dependency rule, four claimed test files where one
exists, `pip install -e .` with no packaging file, and an ADR directory that
doesn't exist. One true rule planted as a control.

**S6 — an `/agentic-architecture` report**, graded C+, ordering three items
"before any Q3 roadmap work begins." Two of those three rest on things that
do not exist: a hallucinated `render`↔`export` circular dependency and a JSON
write bottleneck deleted a week before the report's own commit. Plus a
hallucinated `InvoiceRepository` class, a hallucinated `validators.py`, and a
fabricated complexity metric. Two findings are genuinely true.

## Answer to the question: does clarify.md self-adjust?

**No. The model self-adjusts by ignoring clarify.md.**

clarify.md is structurally bound to spec-kit. Its step 6 requires inserting a
`## Clarifications` section and a `### Session YYYY-MM-DD` subheading into the
document, then routing each answer to "Functional Requirements", "Data Model",
or "Success Criteria > Measurable Outcomes". Step 7 validates that "only
allowed new headings" were added. None of those sections exist in a `CLAUDE.md`
or an architecture report, and stamping a Clarifications block into either one
would corrupt it.

Both clarify runs quietly dropped steps 6–8 and produced a verification table
plus one question. That is good judgement — and it is the agent overriding the
skill, not the skill adapting. What survived was the ≤5-question format and the
recommended-option table. What produced the value was reading the code, which
clarify.md never asks for.

Worth noting against round 1: on S4 the clarify arm *claimed* to have written a
`## Clarifications` section and the file was byte-identical. Following step 6
on a non-spec is wrong, and reporting that you followed it is worse.

Pushback needs no adjustment because nothing in it is spec-shaped. Check source
control, check scope, defend every finding as "Y happens because Z", present one
at a time, count the discards, report unresolved items. That reads the same
against a PRD, a steering file, or a generated report. The one place it shows
the seam is minor: Phase 3 asks "update the spec, write a report, or both?",
which is slightly odd phrasing for a `CLAUDE.md`, and the report path is
`paad/pushback-reviews/<date>-<spec>-pushback.md`.

## What pushback added over a plain capable agent

Less than round 1, on findings. These artifacts are wrong enough that any agent
that reads the code catches them — all three arms scored 7/7 on S5 and caught
every hallucination on S6. Three things were unique to pushback:

**1. It distinguished fabrication from staleness.** Baseline concluded the
report was "consistent with a review run against the pre-SQLite tree." Clarify
said the report "describes a codebase that stopped existing two commits before
the one it cites." Pushback checked:

```
$ git diff --stat 4e0f028 HEAD -- invoicer/ tests/
(empty)
```

The source is byte-identical to what the report claims to have read, so the
findings were false at the moment they were generated — not overtaken by later
work. That changes the remedy from "re-run it" to "don't trust its method."

**2. It found a generalizable heuristic.** The findings citing a file and line
(`cli.py:29`, `tests/`) were the two that held. The findings citing only symbol
names (`InvoiceRepository`, `store._save()`, `validators.py`) were all
fabricated. Its recommendation — treat any finding without a file:line citation
as unverified by default — is a rule that outlives this one report.

**3. Discards.** 4 on each artifact, named and reasoned. On S5 it explicitly
discarded the control I planted (the true `render._money()` rule) rather than
padding the list with it.

## Caveat on this round

The S5 fixture has an artificial seam: I backdated `CLAUDE.md`'s author date to
2026-06-05 while committing it at HEAD. Arms read that differently — baseline
took the author date, pushback noted it as the most recent commit. Immaterial
to scoring, but a real repo wouldn't look like that.

## Verdict

Pushback generalizes to non-spec artifacts cleanly; nothing in it assumes a
spec. clarify.md does not — it survives contact with these artifacts only
because the model declines to follow its integration steps, and one round-1 run
shows what happens when the model tries to follow them anyway.

On artifacts this badly wrong, the finding advantage over an unaided agent is
small. What pushback reliably adds is the audit posture: verify before
repeating, defend or discard, and say how many you threw away.
